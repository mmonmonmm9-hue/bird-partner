# Bird Partner — เว็บสมัครพาร์ทเนอร์ (ตัวจริง)

เว็บสมัครพาร์ทเนอร์ขนส่งของ Bird Express: เลือกประเภทผู้สมัคร → กรอกเลข 13 หลัก → สร้างบัญชีด้วยอีเมล → คุยกับ AI เพื่อให้ข้อมูล → แนบเอกสารบังคับ → ส่งให้เจ้าหน้าที่ตัดสิน

## เริ่มใช้งาน (เครื่องตัวเอง)

ต้องมี Node.js 22.5 ขึ้นไป (ตัวนี้ใช้ `node:sqlite` ในตัว ไม่ต้องลงฐานข้อมูลเพิ่ม)

```bash
npm install
npm run dev
```

แล้วเปิด http://localhost:5173 (หรือดับเบิลคลิก `start-bird-partner.bat`)

- **ยังไม่ใส่คีย์อะไรเลยก็รันได้** — AI จะอยู่ในโหมดสำรอง (ตอบตามกฎ **ไม่ใช่โมเดลภาษา**), รหัสอีเมลจะแสดงบนหน้าเว็บ (โหมดทดสอบ), Google Sheets ปิดอยู่
- บัญชีเจ้าหน้าที่ (admin): ถ้าไม่ตั้ง `ADMIN_EMAIL`/`ADMIN_PASSWORD` ระบบจะสร้าง `admin@birdexpress.local` พร้อมรหัสผ่านสุ่มและ **พิมพ์ครั้งเดียว** ในหน้าต่างเซิร์ฟเวอร์ตอนรันครั้งแรก เข้าสู่ระบบที่หน้า `/login` แล้วจะถูกพาไป `/admin`
- ข้อมูลทั้งหมดอยู่ในโฟลเดอร์ `data/` (ฐานข้อมูล, ไฟล์ที่อัปโหลด, กุญแจเข้ารหัสตอน dev) ลบโฟลเดอร์นี้ = เริ่มใหม่หมด

## ตั้งค่าของจริง

คัดลอก `.env.example` เป็น `.env` แล้วกรอก (ห้าม commit, ห้ามใส่ในโค้ดหน้าเว็บ)

| ต้องการ | ใส่ค่าอะไร |
|---|---|
| AI จริง (Claude) | `ANTHROPIC_API_KEY` (โมเดลตั้งที่ `ANTHROPIC_MODEL`) |
| ส่งอีเมลรหัสยืนยันจริง | `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` |
| เขียนลง Google Sheets | `GOOGLE_SHEET_ID` + `GOOGLE_APPLICATION_CREDENTIALS` (ไฟล์ JSON) หรือ `GOOGLE_SERVICE_ACCOUNT_JSON` |
| ขึ้น production | `NODE_ENV=production`, `DATA_KEY`, `APP_ORIGIN`, HTTPS |

### Google Sheets
1. สร้าง Google Sheet ชื่อ "Bird Partner Database" (ว่างเปล่าได้)
2. ใน Google Cloud สร้าง Service Account, เปิดใช้ Google Sheets API, สร้างคีย์ JSON
3. กด Share ชีตให้อีเมลของ service account (`...@...iam.gserviceaccount.com`) แบบ **Editor**
4. ใส่ `GOOGLE_SHEET_ID` และไฟล์คีย์ใน `.env` แล้วรีสตาร์ต

ระบบจะสร้างแท็บ `Individual` และ `Business` พร้อมหัวคอลัมน์ให้เอง หนึ่งแถวต่อหนึ่ง Partner ID และอัปเดตแถวเดิมทุกครั้งที่ข้อมูลเปลี่ยน ใน Sheets เก็บเฉพาะข้อมูลสรุป **ไม่มีเลขบัตรประชาชนของบุคคล ไม่มีเอกสาร ไม่มีเลขบัญชีธนาคาร** (เลขทะเบียนนิติบุคคลอยู่ในคอลัมน์ Registration Number ตามรูปแบบที่กำหนด) ถ้าเขียนไม่สำเร็จ ข้อมูลยังอยู่ในฐานข้อมูลและเจ้าหน้าที่เห็นสถานะ error ในหน้ารายละเอียด

### AI ทำงานอย่างไร
- รายการข้อมูลที่ต้องรู้ (`shared/profile.ts`, `shared/requirements.ts`) เป็น "รั้วกั้น" แบบตายตัว — AI เลือกวิธีถามและแยกข้อมูลจากคำตอบ แต่ **ระบบเป็นผู้ตัดสินว่ายังขาดอะไร**
- ทุกอย่างที่โมเดลส่งกลับถูกตรวจซ้ำ (`sanitizeProfilePatch`, `sanitizePatch`) ก่อนบันทึก
- AI **ไม่อ่านรูป/ไฟล์ที่แนบ** (เจ้าหน้าที่ตรวจเอง) ไม่ได้รับเลขบัตรประชาชน และ **ไม่อนุมัติ/ปฏิเสธ** — เจ้าหน้าที่ตัดสินที่ `/admin` เท่านั้น
- ถ้าโมเดลปฏิเสธหรือเรียกไม่สำเร็จ จะตกไปโหมดสำรองและมีข้อความบอกในแชต; ตั้งให้ API ลองโมเดลสำรองฝั่งเซิร์ฟเวอร์ได้อัตโนมัติเมื่อโมเดลหลักปฏิเสธ (`fallbacks: 'default'`)
- ข้อความที่พาร์ทเนอร์พิมพ์ (ชื่อ ที่อยู่ เบอร์ เลขบัญชี ฯลฯ) จะถูกส่งไปยัง Anthropic API เมื่อเปิด AI จริง

## ความปลอดภัยที่มี
- เลขบัตร/เลขนิติบุคคลเข้ารหัส AES-256-GCM (`DATA_KEY`) และมี HMAC ไว้กันสมัครซ้ำ; หน้าเจ้าหน้าที่เห็นเลขเต็มและทุกการเปิดดูถูกบันทึกใน audit
- รหัสผ่าน scrypt, เซสชันเก็บแบบ hash ฝั่งเซิร์ฟเวอร์ในคุกกี้ httpOnly/SameSite=Lax, ป้องกัน CSRF (header + Origin), rate limit ทุกจุดสมัคร/เข้าสู่ระบบ/แชต/อัปโหลด, helmet + CSP
- อัปโหลด: เช็กชนิดจากเนื้อไฟล์จริง (JPG/PNG/WEBP/HEIC/PDF ≤ 8 MB), เก็บชื่อไฟล์แบบสุ่ม, ผู้สมัครเปิดได้เฉพาะไฟล์ตัวเอง
- รหัส OTP ไม่แสดงบนหน้าเว็บเมื่อ `NODE_ENV=production`

## โครงสร้าง
```
shared/   กติกาธุรกิจ (รายการข้อมูลที่ต้องถาม, เอกสารตามบริการ, โครงสร้างราคา, โหมดสำรอง) ใช้ร่วมกันทั้งหน้าเว็บและเซิร์ฟเวอร์
server/   Express 5 + node:sqlite (auth, แชต/AI, อัปโหลด, Google Sheets, admin)
web/      Vite + React + Tailwind + framer-motion (ธีมสีขาว, เปลี่ยนหน้าแบบนุ่ม)
```

## คำสั่ง
```bash
npm run dev         # พัฒนา (เซิร์ฟเวอร์ :3001 + เว็บ :5173)
npm run typecheck   # ตรวจชนิดข้อมูลทั้งสองฝั่ง
npm run build       # สร้างหน้าเว็บเป็น web/dist
npm start           # รันเซิร์ฟเวอร์ (ถ้ามี web/dist จะเสิร์ฟหน้าเว็บที่ :3001 ด้วย)
```

## สิ่งที่ยังไม่ได้ทดสอบกับของจริง
ตอนพัฒนาไม่มีคีย์จริง จึง **ยังไม่เคยรันกับ Claude API จริง, Google Sheets จริง และ SMTP จริง** — โค้ดเขียนตามเอกสารของแต่ละบริการและมีทางสำรอง (โหมดสำรอง / ข้ามการซิงก์ / พิมพ์รหัสใน log) แต่ควรลองกับคีย์จริงตามขั้นตอนข้างบนก่อนเปิดใช้งานจริง ส่วนอื่น (สมัคร, ยืนยันอีเมลในโหมดทดสอบ, แชตโหมดสำรอง, แนบเอกสาร, ส่งใบสมัคร, เจ้าหน้าที่ตัดสิน, การล็อกแก้ไข, CSRF, สิทธิ์ admin) ทดสอบแล้วทั้งผ่าน API และเบราว์เซอร์

ข้อจำกัดที่ควรรู้: โหมดสำรองเข้าใจคำตอบแบบกฎ ถ้าตอบแหวกจากตัวอย่างอาจต้องถามซ้ำ (AI จริงจะยืดหยุ่นกว่า)

## ลืมรหัสผ่าน และอีเมลแจ้งผล
- หน้า `/forgot` (ลิงก์ "ลืมรหัสผ่าน?" ในหน้าเข้าสู่ระบบ): ส่งรหัส 6 หลักไปอีเมล ใช้ได้ 10 นาที กรอกผิดได้ 5 ครั้ง ตั้งรหัสใหม่สำเร็จแล้วทุกอุปกรณ์ถูกออกจากระบบ และระบบตอบเหมือนกันไม่ว่าอีเมลนั้นมีบัญชีหรือไม่
- เมื่อเจ้าหน้าที่ตัดสิน (อนุมัติ / ขอข้อมูลเพิ่ม / ไม่ผ่าน) ระบบส่งอีเมลแจ้งผู้สมัครพร้อมเหตุผล ถ้าไม่ได้ตั้ง SMTP จะแค่บันทึกใน log ว่าไม่ได้ส่ง (ผลยังแสดงในระบบเสมอ)
- ทั้งสองส่วนทดสอบแล้วในโหมดไม่มี SMTP; การส่งอีเมลจริงยังไม่เคยทดสอบ
